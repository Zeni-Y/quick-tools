## 根本原因と修正内容

### 旧コードの問題

```javascript
// rect のみ使用（複数行ハイライトに対応できない）
const [rx1, ry1, rx2, ry2] = ann.rect;
```

PDF のハイライト注釈は `quadPoints` に行ごとの正確な座標（8 値で 4 隅）を持つ。`rect` は全体のバウンディングボックスであり、複数行にまたがるハイライトでは精度が下がる。

### 新コードの修正

```javascript
// quadPoints から行ごとの rect を構築
if (ann.quadPoints && ann.quadPoints.length >= 8) {
  for (let i = 0; i + 7 < ann.quadPoints.length; i += 8) {
    const xs = [qp[i], qp[i + 2], qp[i + 4], qp[i + 6]];
    const ys = [qp[i + 1], qp[i + 3], qp[i + 5], qp[i + 7]];
    rects.push([
      Math.min(...xs),
      Math.min(...ys),
      Math.max(...xs),
      Math.max(...ys),
    ]);
  }
}
```

ターゲット注釈の `quadPoints` は 32 値（4 行分）で、4 つの矩形を生成:

| 行  | x 範囲  | y 範囲       | テキスト                                                                       |
| --- | ------- | ------------ | ------------------------------------------------------------------------------ |
| 1   | 79..467 | 342.9..355.3 | 音声対話による実環境での実証実験を通して，アンケート対話システムの実環境におけ |
| 2   | 79..467 | 325.9..338.4 | る有効性を示すとともに，実環境では，質問に対して必ずしも明確な回答が得られるわ |
| 3   | 79..467 | 309.0..321.4 | けではなく，曖昧な応答や質問とは無関係な応答への対処が必要であることを明らかに |
| 4   | 79..109 | 292.1..304.5 | した．（部分）                                                                 |

### Node.js vs ブラウザの差異

- **Node.js**: CJK cMap がないと日本語テキストが空文字列になる → テキストマッチ不可
- **ブラウザ**: CDN から cMap を自動ロード → 日本語テキスト正常デコード → テキストマッチ可能

Node.js での検証は `cMapUrl` を指定することで同等の結果が確認できた。
